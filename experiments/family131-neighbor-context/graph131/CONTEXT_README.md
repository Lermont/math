# Контекст соседей Elliptic2

Отдельное продолжение первоначального эксперимента. План: `CONTEXT_PLAN.md`.
Результат: [подробный отчёт](../results/elliptic2-context/report.md) и
[визуальный отчёт](../results/elliptic2-context/report.html).
Выходные файлы: `results/elliptic2-context/`. Прежний `results/elliptic2/`
используется только как источник малых CSV и списка ранее выбранных подграфов.

```powershell
.\.venv-graph131\Scripts\python.exe -m graph131.context_download
.\.venv-graph131\Scripts\python.exe -m graph131.context_data
.\.venv-graph131\Scripts\python.exe -m unittest discover -s tests -p 'test_graph131*.py' -v
.\.venv-graph131\Scripts\python.exe -m graph131.context_run
.\.venv-graph131\Scripts\python.exe -m graph131.context_report
```

Первый шаг читает весь официальный ZIP (~24.5 GB по сети, ~82.9 GB после
распаковки), но не сохраняет его: фильтрует рёбра по выбранным ядрам. Небольшая
выборка подграфов не позволяет произвольно читать соседей из единого deflate
потока без индекса. Проверяются HTTP byte ranges, размер, EOF и CRC ZIP;
SHA-256 CSV вычисляется потоком. Данные хранятся локально.

Получение данных не перезаписывает существующий файл incident-edges.csv.
Для нового получения используйте отдельную копию проекта/каталог результатов.
При сетевой ошибке отдельный диапазон повторяется до пяти раз; глобальное
возобновление после завершения процесса не реализовано. Частичный результат
без acquisition.json не используется для подготовки данных.

Контекст — инцидентные рёбра на один шаг, максимум 32 внешних соседа,
без связей между внешними соседями. Общие между частями выборки узлы и
транзакции исключаются до отбора соседей. Направление и кратность платежей
сохранены для directed-контроля; для №131 используется простой граф.

Каждый метод работает в отдельном процессе на одном CPU-потоке.
Порядок методов сдвигается между seeds. Общие подготовленные данные кешируются
на диске; признаки каждого метода вычисляются заново. Перезапуск сравнения
пропускает только существующие измерения с совпадающими hashes данных и кода.
Для нового кода нужен новый каталог результатов.

RevTrack был проверен как возможный компактный источник контекста. Его
`data_df.pkl` представляет преобразованные пары отправитель–получатель,
а не исходные соседние транзакции, поэтому в эксперимент он не входит.
Никакие скачанные pickle/модели не используются в воспроизводимом pipeline.

Из-за редкого положительного класса пилот имеет широкую неопределённость.
Отчёт включает парные bootstrap-интервалы по строкам и, дополнительно,
по компонентам общих узлов/транзакций внутри теста. Последние учитывают
возможную зависимость тестовых примеров; это не замена новому разбиению
или временному holdout.

Первоначальные hashes исходников находятся в `run-metadata.json`. После
измерений исправлен только читатель CSV в `context_report.py`: режим
`float_precision='round_trip'` сохраняет точный порядок соседних float-оценок
и воспроизводит AP исходных worker-процессов. Исходный файл отчёта сохранён
как `initial-context_report.py`, итоговая проверка — `final-verification.json`.
Модели, признаки, прогнозы и измерения времени не менялись. Для повторного
построения отчёта запускайте только `graph131.context_report`; новый benchmark
на изменённых исходниках требует отдельного каталога результатов.
