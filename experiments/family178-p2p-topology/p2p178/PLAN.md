## Вопрос и границы

Полезен ли спектральный отбор топологии для небольшого P2P broadcast поверх
обычного случайного регулярного графа? Отдельно: пригодна ли опубликованная
конструкция №178 для такого локального прототипа?

Полная конструкция №178 не переносится: она требует четырёх стадий условных
ожиданий, матричных оценок, перечисления переключений и точной рациональной
проверки. Порог n0(d) и практический показатель времени не конкретизированы.
В каталоге formalization.yaml отсутствует запись о данном результате.
Спектральный отбор ниже — самостоятельная эвристика, не реализация №178.
На малых графах отдельно проверяется точный критерий из раздела 9:
B^T(4(d-1)I-A²)B положительно определена, B=[e_i-e_n]. Это не проверка
доказательства существования или времени построения.

## Топологии и повторы

- Основной набор: n=512,2048; d=4,8.
- `random_regular`: NetworkX random_regular_graph, первый простой связный
  кандидат (при несвязности фиксируется отказ, без подбора).
- `circulant`: смещения ±1,...,±d/2; точная степень и столько же соединений.
- `spectral_rejection`: та же последовательность random_regular_graph,
  первый простой связный недвудольный кандидат с численно оценённым
  lambda_abs < 2 sqrt(d-1) - 1e-7; максимум 32 кандидата. Невыход в бюджет
  сохраняется как отказ, без подмены лучшим кандидатом. Первый кандидат
  совпадает с random_regular для парного сравнения.
- Дополнительный сопоставимый набор: n=2184,d=6, те же три метода плюс
  `lps`: классический X^(5,13), Cayley(PGL(2,F_13)), двудольный. Компактная
  собственная реализация формул LPS, не исполнение Julia-пакета. Параметры
  удовлетворяют p,q простые, p≠q, p,q≡1 mod4, q>2sqrt(p), (p/q)=-1.
  Этот размер близок к 2048 и позволяет сохранить простой граф и степень.
- По 5 семян: 17801,17802,17803,17804,17805. Метки всех вершин независимо
  от конструкции одинаково перемешиваются до назначения физической сети.
  Для детерминированных графов повторы меняют размещение/нагрузку, не
  изоморфный тип. Получается 80 построений, максимум 480 сценариев.
- Margulis–Gabber–Galil: готовый генератор имеет n² вершин, петли и кратные
  рёбра. Удаление последних меняет степень; не выдавать его за честный
  аналог с 8 различными соседями. Paley при d=8 имеет только 17 вершин.

## Общий протокол и нагрузка

Конечная дискретно-событийная симуляция eager flooding с кэшем ID сообщений.
При первом получении узел ставит в FIFO исходящие копии всем соседям, кроме
первого отправителя. Источник ставит копии всем соседям. Дубликаты не
пересылаются. Соседи обслуживаются в воспроизводимом перемешанном порядке
для каждого сообщения. Повторной передачи, pull, mesh repair, GRAFT/PRUNE,
IHAVE/IWANT/IDONTWANT, подтверждений, NAT и криптографии нет: это не Gossipsub.

- 8 сообщений по 16 KiB + 64 байта условного wire overhead, запуск через
  100 ms; источники из доступных узлов по общему seed. Это ограниченная
  вспышка нагрузки, не тест стационарной пропускной способности.
- 10 Mbit/s совокупного исходящего канала на узел, сериализация копий
  учитывается. Приём и вычисление не ограничены. Очередь без потерь и
  лимита размера; кэш хранит все восемь ID. Нет заранее заполненных кэшей.
- Односторонняя задержка: `uniform` = 10 ms; `heterogeneous` = 5 ms внутри
  одного из четырёх случайно назначенных регионов, 50 ms между регионами,
  плюс фиксированный для пары узлов jitter [0,20) ms. Регионы, jitter,
  порядок обслуживания, источники и отказы — общие поля seed для методов.
- Отказы: 0%,10%,30% узлов, ровно floor(fn) случайных узлов отключаются до
  сообщений. Одно и то же множество ID для методов. Соседи ещё не знают
  об отказе: передачи к отключённым узлам расходуют канал и байты, но
  отбрасываются. Граф не перестраивается; источники всегда доступны.
- Все сценарии отрабатывают до опустошения очередей, без таймаута модельного
  времени; технический лимит одного дочернего процесса 180 секунд.

## Проверки и измерения

До замеров выполнить unittest в `p2p178/tests/`: структуры, LPS-параметры,
точный малый критерий, спектр против dense oracle и известного спектра,
двудольный -d, несвязные графы, shortest-path oracle без очередей,
серилизация FIFO, счётчики передач/дублей/потерь и недостижимые пороги.

Простота, связность, степень, двудольность проверяются комбинаторно.
Для n>64: SciPy eigsh, по 3 LA и SA, фиксированный v0, tol=1e-10,
maxiter=max(5000,20n), ncv=40. Исключать ровно одну +d и, только при
доказанной связной двудольности, одну -d. Проверять невязки <=1e-8.
Не сходится / близко к границе — не принимать. Для n<=64 полный eigh.
Невязка — диагностический показатель, не формальная гарантия нахождения
всех крайних значений или сертификат спектра. На замеренных больших графах
точная рациональная сертификация не выполняется.

Сохранить для каждого построения и всех отвергнутых кандидатов seed,
список рёбер и SHA-256, параметры, спектральную оценку/невязку и причину,
время генерации, структурной проверки, спектрального теста; суммарное время
включает все попытки и запись графов. Нельзя скрывать отвергнутые кандидаты.

Каждое построение и пакет шести симуляций запускаются в разных свежих
процессах. Пиковая память: Windows process peak_wset (RSS high water,
включая интерпретатор/импорты), исходная RSS и дополнительно опрос RSS.
Таймеры вычислений исключают запуск/импорты; wall time процесса и чтение/
запись раскрываются отдельно. Пакет симуляций содержит шесть сценариев;
его точный peak_wset не приписывать одному сценарию. На других ОС —
опрос RSS, явно приблизительный. Один процесс измеряется за раз, BLAS=1.

Для каждого сообщения: t50/t95/t99 от запуска до ceil(q*число доступных)
получателей (источник включён), null если порог недостижим; достижимая и
недостижимая доля, передачи, байты, дубли и потери к отключённым узлам.
Также длительность моделирования и пиковая память пакета. Проверять
совпадение достижимости с компонентой источника. Нет отказов и граф связен:
передач на сообщение nd-(n-1), дублей (d-2)n+2. Это инвариант протокола,
а не ожидаемый выигрыш от спектра.

## Анализ без подгонки

Показывать медиану и min–max средних по 8 сообщениям для 5 семян; при
недостижении порога показывать число цензурированных сообщений и не
представлять среднее по доставленным как время охвата всей сети.
Парные отношения к random_regular только при достижимом пороге в обеих
парах. Пять повторов — пилот, не доказательство статистического превосходства.
Практически интересным считать устойчивое уменьшение медианы t95 минимум
на 10% сверх random_regular без ухудшения достижимости/байтов; это ориентир,
не проверка значимости. Отдельно сообщить цену отбора.

Не менять топологии/параметры/семена по результатам. Исправления ошибок
фиксировать отдельной записью, сохранять невалидный запуск и полностью
повторять затронутое сравнение. Результаты только в results/p2p178/.
Выводы не распространяются на Byzantine/Sybil, безопасность консенсуса,
адаптацию к churn, Интернет или протокол Gossipsub.
