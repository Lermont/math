# Эксперимент №325: план до измерений

Зафиксирован 11 октября 2026 (Europe/Moscow), до генерации выборки и измерений.
Область работы: только `filter325/`, `references/filter325/`,
`results/filter325/`, `.venv-filter325/`. Все примеры синтетические.

## Вопрос и критерий

Вычисляем `exp(A)x`. Применяем скалярный случай №325 к ошибке полинома,
не реализуем доказательство статьи. Отделяем вклад константы 2 от
построения области и выбора конкретного полинома. Успех по стоимости:
не менее 10% экономии медианного полного времени при выполнении допуска
на всех восьми входах данного случая, отдельно для одного входа и восьми
последовательных применений. Отдельный результат — полезная строгая
граница ошибки аппроксимации, даже без ускорения. Единичный удачный случай
не считается общим превосходством. Статистические заявления за пределами
этой небольшой фиксированной выборки не делаются.

## Фиксированная выборка

Seeds: 32501, 32502. По каждому seed:

| Семейство | n | A |
|---|---:|---|
| symmetric_ring | 64 | 2(P+P^T)-4I, симметричная диффузия |
| normal_cycle | 128 | 4(P-I), направленный цикл, нормальная матрица |
| directed_regular | 128 | 8(P-I), четыре случайных различных выхода на строку |
| directed_hub | 128 | 4(P-I), вероятность 3/4 в общий hub, 1/4 по циклу |
| jordan | 64 | -4I+8S, S — верхний сдвиг, ненормальный стресс |
| grcar | 64 | -4I+2(S+S²+S³-S^T), ненормальный стресс |

Дополнительно: directed_regular n=1024 seed=32501, directed_hub n=1024
seed=32502, jordan n=2048 seed=32501. Для структур без случайных рёбер
два seed меняют входы, а не матрицу; это не независимые матрицы.
В каждом случае восемь одинаковых для методов знаковых векторов с двоичным
масштабированием, с отдельным воспроизводимым seed. Ненормальность:
`||A^T A-AA^T||F/||A||F²` (диагностика, не верхняя граница нормы).

Допуски: 1e-4, 1e-7, 1e-10 для `||error||2 / ||x||2`.
Также сообщаются абсолютная ошибка и ошибка относительно `||exp(A)x||2`.
В степень полинома закладывается 0.9 допуска; оставшийся запас не является
сам по себе доказательством контроля округлений.

## Методы и сертификаты

1. `crouzeix2`: shifted Taylor, `p_m(z)=exp(c) sum_{k=0}^m (z-c)^k/k!`.
   `c=(min diag A+max diag A)/2`. Для `B=A-cI`, `M=|B|`,
   `S=(M+M^T)/2`: `w(B)<=lambda_max(S)<=max_i (Sv)_i/v_i` для любого
   строго положительного v. 12 фиксированных итераций над `S+alpha I`
   дают лишь кандидат v; после квантования v в положительные целые
   неравенства проверяются точно рациональной арифметикой.
   Радиус — минимум этой оценки, обычной суммы строки S и
   `sqrt(||B||1 ||B||inf)` с направленным наружу рациональным sqrt.
2. `crouzeix_old`: строго те же область, полином и процедура; только
   константа заменена на `1+sqrt(2)` (верхняя рациональная оценка).
3. `norm_taylor`: тот же shifted Taylor, стандартная оценка через
   `R>=||B||2`, `R=sqrt(||B||1||B||inf)`, с константой 1.
4. `normal1`: на двух нормальных семействах константа 1 на том же диске,
   по спектральной теореме. Польза №325 на этих контролях не заявляется.
5. Публичный `scipy.sparse.linalg.expm_multiply` (Al-Mohy–Higham).
   API не имеет параметра допуска: используется штатная точность.
   Время измеряется на явной CSR, включая внутреннюю подготовку;
   инструментирование для счёта произведений делается отдельно,
   сохраняя тот же sparse-путь. Общий trace вычисляется и учитывается.
6. Arnoldi, две проходки модифицированного Грама–Шмидта; проверка
   проектированной экспоненты на размерностях 4,8,...,80 (или n).
   Остановка по разности соседних приближений <=0.1 допуска, либо
   счастливый распад. Критерий остановки эвристический, проверяется
   по независимому эталону; полная стоимость базиса и малых экспонент
   включена. Для другого x базис строится снова.

Уточнение до измерений после чтения исходника SciPy 1.18.1: добавляем
`scipy_cached`, который один раз выполняет ту же внутреннюю подготовку
`expm_multiply` и повторно вызывает неизменённое вычислительное ядро.
Это версия-зависимый адаптер private API, не новый готовый публичный API.
Он нужен, чтобы переиспользование подготовки было доступно обоим подходам.
Публичный `scipy` остаётся самостоятельным обязательным сравнением.

Строгая скалярная оценка на всём диске, а не сетке его границы:
при `m+2>r`, `tail <= exp(c) r^(m+1)/(m+1)! / (1-r/(m+2))`.
Экспонента и квадратный корень ограничиваются точными рациональными
рядами/целочисленным sqrt. Итоговая граница — `C*tail*||x||2`.
Эта граница относится к точной арифметике. Применение полинома float64
не называется полностью сертифицированным. Проверяем фактическую ошибку
и отдельно округления против вычисления того же полинома с 80 знаками.
Переход к exp из полиномиальной теоремы обосновывается равномерной
сходимостью ряда на диске и сходимостью операторного ряда.

## Эталон и измерения

Малые матрицы: независимая плотная Padé `scipy.linalg.expm(A) @ X`,
перепроверенная отдельным 80-значным вычислением действия ряда.
Большие: отдельная высокоточная реализация действия ряда с нормовой
оценкой остатка <1e-60; первый вектор повторяется со 110 знаками.
Сохраняем расхождения эталонов, оценку усечения и ограничение проверки
округления. Эталон и диагностика не входят во время конкурентов.

Один поток BLAS/OpenMP; последовательные измерения, одинаковые CSR/X.
Одна разминка, пять сырых времён; порядок методов перемешан фиксированно.
Отдельно измеряются область/норма, поиск степени, коэффициенты, применение.
Полное время: новая подготовка + один вход; повторное: новая подготовка +
восемь последовательных входов. Повторно используется только подготовка
матрицы/полинома, не результат и не векторный базис. Дополнительно можно
показать расчётную окупаемость из измеренных стадий, явно как модель.

Пиковая память: отдельный свежий процесс на сочетание случай/метод/допуск,
абсолютный Windows peak working set (включает импорт и данные) и
`tracemalloc`-пик этапа setup+batch. Пики не вычитаются как точная память
алгоритма; трассировка не покрывает все внутренние native-буферы.
Счёт SpMV отдельно от времени; учитываются произведения при подготовке
и сопряжённые произведения. Повторное применение отражает ровно 8 входов.

Сохраняются конфигурация, её хеш, хеш плана до запуска, CSR/входы, эталоны,
предсказания, сырые времена, сертификаты дисков, версии, сведения о CPU,
память, тесты и русский отчёт. При ошибке реализации исправление и повтор
запуска документируются; выборка/допуски не меняются по результату.
Lean/Comparator в этой проверке не компилируются; проверяем наличие
артефактов, формулировки и условия, не заявляем аудит полного доказательства.
